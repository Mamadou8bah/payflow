# Mobile UI review — 10 October 2026

Reviewed the customer, agent and merchant mobile clients in a headless Chrome
browser using Expo web exports, at widths 320, 390 and 768 pixels. Backend traffic
was intercepted; no real credentials, payments or cash operations were used.

Changes:
- Kept white page backgrounds, neutral surfaces and orange accents.
- Made wallet cards fit narrow phones; improved wallet list layout and long labels.
- Added names and selection semantics to every navigation tab; increased tap targets.
- Added keyboard-aware, scrollable login/support forms and clearer input labels.
- Added empty states, loading states, disabled submit buttons and repeat-tap guards.
- Connected wallet creation to the existing API, including local demo wallets.
- Corrected transfer recipient instructions to match the wallet-ID API.
- Corrected wallet action selection, payment status labels and profile placeholders.
- Spending/income charts exclude incomplete payments and keep currencies separate.
- Removed nonfunctional profile/security controls and a merchant action with no effect.
- Labelled agent statistics as session counts, matching their current local storage.
- Constrained the customer web app to viewport height so long QR forms cannot push the header off-screen.
- Kept the top-up back button outside scrolling content so QR generation cannot hide it.
- Deferred native camera loading so offline browser screens do not request the scanner CDN.
- Corrected malformed text encoding and excessive form bottom spacing.

Checks:
- All three apps passed TypeScript checks and Expo web exports.
- Browser flows passed: customer wallet creation, transfer and pending-deposit income exclusion, agent lookup and
  settlement confirmation, and online login/logo rendering for all three clients.
- No horizontal document overflow at the reviewed widths; no browser runtime errors
  in the final flow run.
- Eleven demo transport tests passed, including separation of new wallet balances.

Browser screenshots and the local harness are under `.local-validation/ui-review`
in the parent workspace. They are local review artifacts, outside this repository.
Native iOS/Android keyboard, safe-area, permission and camera behavior still needs
physical-device or emulator acceptance testing. This review does not certify that
all possible UI defects have been eliminated.
